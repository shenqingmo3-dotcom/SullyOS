## 二、新增的常驻后端能力

后端位于 `backend/`，由 PostgreSQL、Fastify API 和独立 heartbeat worker 组成。

### 1. 配对、鉴权与设置页

- API 使用 Bearer `APP_TOKEN`；浏览器 Origin 使用显式白名单，不接受通配符。
- 支持一次性配对码换取后端连接配置。
- 设置页可测试后端、查看模型状态、配置模型池、切换固定模型或自动故障转移。
- 模型密钥在数据库中加密；迁移数据库时必须同时保留原 `MODEL_VAULT_KEY`。
- 普通聊天目前仍默认走 SullyOS 前端原模型池；后端聊天接口存在，但没有替换现有主聊天路径。

### 2. 完整上下文与记忆同步

- 同步角色、用户资料、普通聊天、记忆节点和删除标记。
- 完整记忆宫殿覆盖节点、向量、关联、事件盒、门牌、期盼、消化报告、处理批次与旧话题盒。
- 支持分片上传、稳定 ID 去重、快照 reconcile 和数量核对。
- 前端新增本地同步队列；记忆新增、修改、删除会排队，成功后才确认游标。
- 删除角色、聊天、记忆宫殿和日记均有后端删除路径，目标是避免数据刷新后“复活”。

### 3. 有类型的事件回流

后端事件保留以下类型：普通消息、主动消息、日记、便签、自主活动、MCP 活动、平台分享、记忆变化、预约苏醒和系统事件。

前端每 30 秒读取事件游标并落入独立 `backend_events` store：

- 主动消息恢复为角色气泡并触发通知事件；
- 自主活动和 MCP 结果显示为活动卡片；
- X / 小红书 / 网页分享恢复为对应内容卡片；
- 后端日记和便签合并到本地日记与原聊天卡片；
- iPhone 截图恢复为图片消息或带图活动卡片。

### 4. 自主 heartbeat

- Worker 周期检查不等于每轮调用模型；先经过角色开关、空闲阈值、允许时段、冷却和概率门。
- 角色可选择沉默、主动消息、独立日记、日记便签或工具探索。
- 支持角色自己预约下一次精确苏醒；预约到点不会再经过普通随机概率。
- 每个角色可配置活动间隔、空闲阈值、时段、冷却、概率、每日工具预算和允许能力。
- heartbeat 上下文包含角色设定、近期聊天、记忆、线上/线下状态、当天日程和相关 NPC。
- 生产部署脚本默认不启动 Worker；首次迁移应先只启用一个常聊角色观察。

### 5. 后端日记

- 后端可自主生成角色独立日记，限制每天最多一篇并避免重复近期题材。
- 用户日记、角色日记和便签均有稳定后端主键与同步接口。
- 角色可对某篇日记贴便签，但不会为了回应用户日记再生成一篇对应日记。

### 6. Web Push

- 后端保存浏览器 push subscription，并使用 outbox 投递主动消息、日记和工具活动通知。
- Service Worker 能识别 `sullyos-backend` 推送并唤醒前端读取事件。
- 必须在 HTTPS/PWA 环境配置 VAPID 后才能真实使用；当前代码存在不代表正式域名已完成推送验收。

## 六、域名迁移前必须认清的边界

1. 当前所有二改已合并到主工作树 `master`；旧部署包仍不是二改成品，部署时应从主工作树最新提交重新构建。
2. 当前 VPS 上是否已经运行这些源码没有新的服务器证据，因此不能声称线上已更新。
3. 正式域名迁移前应先从手机最新完整备份选定权威前端数据，再执行一次完整同步和数量核对。
4. 首次部署只启动 PostgreSQL、API 和 Caddy；heartbeat Worker 保持关闭。
5. 域名切换需要同时修改 DNS、Caddy 的 API 域名、后端 `ALLOWED_ORIGINS`、前端后端地址，以及 iPhone 快捷指令中的 pending/upload URL。
6. Web Push、iPhone 屏幕查看、X/小红书、Apple Health 和 Open Watch Cinema 都依赖各自的真实外部服务，应逐项联调，不能由单元测试替代。
7. 在真实影院未启动前，“一起看电影”的记忆闭环只能算代码与模拟数据验证完成；小说共读不受此限制。

## 七、审计结论

二改已经形成两个层次：

- SullyOS 前端体验层：线上/线下统一、MCP 卡片、一起看、动态日程、NPC 关系网、独立日记和 PWA 图标。
- SullyOS 常驻能力层：PostgreSQL 权威数据、完整同步、事件回流、自主 heartbeat、模型池、Web Push、外部工具与手机感知。

从源码、自动测试和生产构建看，这一轮功能已经完成收束；从真实运行环境看，域名、手机权威备份、VPS 新版本部署和各外部服务联调仍是下一阶段，尚未发生。
